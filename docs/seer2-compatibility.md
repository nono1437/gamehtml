# 《约瑟传说》手机测试

在 Flash 游戏盒首页点「约瑟传说」，或打开 `http://seer2.61.com/index_open.html`、`https://seer2.61.com/Client.swf`。该入口默认使用内置 Ruffle。要复测 WAFlash，可在播放器的悬浮菜单里切换「Flash 引擎」。该选择只应用于《约瑟传说》。

## 启动链路

官方入口和启动资源的 HTTPS 请求实测返回 302，指向同一域名的 HTTP 地址。播放器通过同源地址转发官方公共资源的 GET 请求，保留目录结构和版本查询，走系统证书及主机名校验。公共资源请求不携带 Cookie。账号通信不走这个代理。

启动链依次读取 `Client.swf`、`config/seer.xml`、`version/zzz_config.txt` 和版本数据，再加载 `dll/Assets.swf`、配置及 `dll/LoginModule.swf`。版本文件以 `.swf` 结尾，但由启动器作为压缩二进制数据读取。播放器为这种数据保留单独的校验。普通 SWF 检查文件签名和长度。

3.3.3 的真机日志显示 `Assets.swf` 被代理以 HTTP 403 拒绝。启动器先附加 36 进制资源时间戳，随后 AssetsLoader 再附加一个问号和随机数。3.3.4 保留原样转发该组合，也支持其他启动资源的单独时间戳。

WAFlash 2.8.27 在 Chromium 中成功接收完整的 301,535 字节登录模块后，仍停在动态 100% 画面。启动器要在其首个 Loader 完成后再调用 `Loader.loadBytes` 初始化登录界面。定位用的临时探针在首个 Loader 的完成回调中显示文本，WAFlash 没有显示该文本。内置 Ruffle 0.4.1 用同一官方资源继续加载 `res/login/firstPage.swf` 等资源，并显示官方「开始」页。

官方登录模块打开账号表单时会读取 `sr2login.61.com/ip.txt`，成功后才收起等待动画。3.3.6 的真机报告显示三条 HTTPS 查询均超时。3.3.7 按官方 `config/Server.xml` 中的原始 HTTP 地址转发三条公开查询。代理只处理限定的 `/ip.txt` GET 请求，不转发 Cookie 或请求体。同域名重定向可以升级到 HTTPS，HTTPS 证书仍由系统验证。查询失败或超时后，播放器显示原因及「重新加载」。3.3.7 的真机报告确认三条 HTTP 查询均返回 200 和有效地址，启动时的默认查询和点电信登录后的地址查询均已交付给 WebView。

3.3.14 在官服地址查询遇到超时、服务错误或无效响应时，增加一次德国镜像的 HTTPS 公开查询。返回的公网 IPv4 地址必须和本机解析的官服域名相符，且端口必须为 1863。默认线路允许匹配任一官服线路，明确选择电信或网通时只核验所选线路。通过后，手机仍直连官服游戏端口。诊断面板可区分「备用地址已通过官服域名核验」和后续 TCP 连接结果。

官方 `LoginModule.swf` 的 `LoginAgent.onIOError` 将 Socket I/O 失败显示为「服务器没有开启」。用官方 SWF 和本地模拟地址回放登录时，内置 Ruffle 0.4.1 输出 `Missing WebSocket proxy`，随后原版界面弹出同样的消息。回放期间没有发起 WebSocket 或向外部发送登录请求。Ruffle 网页版会在没有匹配代理时直接向 Flash 报告连接失败。[Ruffle 0.4.1 的 Socket 实现](https://github.com/ruffle-rs/ruffle/blob/v0.4.1/web/src/navigator.rs#L494-L516)

3.3.7 的真机报告显示，电信和网通的 1863 端口可建立 TCP 连接，TLS 握手或证书校验失败。3.3.8 的专用 Ruffle 构建把 AS3 `flash.net.Socket` 交给 Android 原生 TCP 套接字。登录模块继续使用淘米原版协议，**密码摘要和登录票据经没有 TLS 的 TCP 连接发送**。其他网页的 TLS 验证使用系统默认行为。

中继仅接受内置《约瑟传说》播放器主框架的请求，初始目标来自官方地址查询，区服直连目标来自登录服务器下发的区服列表。3.3.9 支持从官方 `config/Server.xml` 读取的电信、网通两条备用线路。原版客户端会在区服直连失败后自行回退。区服列表中的定长 IP 字段按 Flash 的读取规则在首个空字符处截断。游戏收发的数据原样通过，不写入日志。离开播放器会关闭相应连接。资源诊断会记录 TCP 线路、有效公网端点、连接、拒绝、失败、关闭和第一次收到数据的字节数。网页端 Ruffle 0.4.1 的补丁及复现构建分别见 `scripts/seer2-ruffle-socket.patch` 和 `scripts/build-seer2-ruffle.sh`。

使用首页《约瑟传说》入口的 Ruffle 引擎进行官服联机测试。WebView 需支持 AndroidX WebKit 的 `WEB_MESSAGE_LISTENER`。旧版 WebView 可继续打开游戏页，直连需要更新 Android System WebView。普通 Ruffle 播放和 WAFlash 仍使用各自的引擎资源。

验证时，在 Chromium 中运行官方 SWF，用本地模拟登录服和区服经 Kotlin TCP 中继收发。3.3.8 的真机已能登录官服并显示区服列表，进入 52 号服时三个核心模块加载完毕，接着两次 TCP 连接被中继拒绝。本地回放让区服直连失败，确认 3.3.8 拒绝备用线路，3.3.9 则连接备用线路并发送转接和区服登录请求（999、1001）。3.3.9 的真机报告确认已进入官服场景。

## 进图后画面与面板

3.3.9 的真机日志中，游戏盒以 403 拒绝了背包、地图、训练等八个面板的 SWF。3.3.10 允许代理 `seer2.61.com/module/` 下的公开 SWF，保留原版路径与版本参数。诊断还发现装备、精灵、NPC 和 NONO 的部分 `.swf` 文件实际包含动画帧表和 PNG 图集。专用代理识别并转发这些文件，普通 SWF 导入仍检查 SWF 格式。

《约瑟传说》的内置 Ruffle 播放器按原版 1200×660 舞台等比居中，超宽屏两侧留黑边。底部提示文字允许触摸事件传给游戏。该入口默认隐藏虚拟手柄，按需从「⋮」→「显示手柄」开启。

3.3.11 可在手机上复用官服 `/module/` 和 `/res/` 下同版本的已校验文件。文件首次仍需从官网成功下载，且官网的 HTTP 响应需允许缓存至少 24 小时。本地最多保留 128 MiB，同一个文件下载 24 小时后会重新请求。诊断中可看到「使用本地资源缓存」。登录地址、启动配置和区服连接始终走官服实时链路。

使用内置 Ruffle 时，可以从「⋮ → 约瑟快捷路径 → 图鉴快捷输入」查看精灵编号。先点游戏图鉴的搜索框，再点对应精灵即可填入编号。游戏里的「查询」和「GO」按图鉴当前配置打开条目和活动。约瑟 `1000` 和约瑟王 `999` 的 GO 通向王者遗迹（副本）。小约瑟 `811` 的条目未配置 GO。雷神·雷伊 `2558`、炎帝·凯萨 `2559` 和冥王·撒旦 `2560` 的 GO 都指向 `YueseCraft2016MainPanel`。

## 检测官服连接

在《约瑟传说》播放器中点「⋮」→「资源诊断」→「官服连接检测」。检测使用手机当前网络，分别用 HTTP 和 HTTPS 访问三条淘米地址查询，并对电信、网通的 1863 端口测试 TCP 和 TLS。TLS 检测使用系统证书和主机名校验。检测只发出公开地址查询和连接握手，不发送登录请求。

等待各项结果出现后，点「导出」保存报告。即使资源记录关闭，导出也包含主动检测的结果。TCP 连通、TLS 校验和账号认证是三个阶段，检测结果可确认前两项。旧版 TCP 模式通过资源诊断里的「官服 TCP 已连接」确认播放器到服务端的连接。

## 采集诊断

1. 在游戏画面点「⋮」→「资源诊断」→「开始记录」。
2. 关闭面板，在悬浮菜单中点「刷新」，重现卡住或失败。
3. 回到「资源诊断」，点「导出」，把 `flash-diagnostics.txt` 保存到手机文件夹。
4. 日志里的「下载并交付 WebView」表示播放器收到了有效响应。引擎报告的启动 SWF 事件表示根影片的状态。界面是否出现要以屏幕观察为准。

导出的日志包含资源路径、网络状态码、下载字节数和耗时，以及 WebView 和引擎错误类别。URL 查询、认证请求头、请求体和原始 JavaScript 控制台文本不写入导出。

## 本地影片与安装

本地 SWF 仍可从首页导入并选择引擎。要加载同目录的其他文件，在游戏菜单中点「本地资源目录」，选择存放 SWF 及子目录的文件夹。用浏览器下载的 `Client.swf` 单独导入时，缺少同一目录下的官方依赖，适合用首页专用入口测试官方链路。

Debug APK 的包名为 `com.game4399.app.debug`。它可以和正式包 `com.game4399.app` 并存。覆盖安装旧 Debug 包取决于签名相同且当前版本号不高于新包。

使用 `./gradlew -Pseer2Preview=true assembleDebug` 或在 GitHub Actions 中打开 `seer2_preview` 构建「游戏盒 · 约瑟测试版」。该应用以 `com.game4399.app.seer2preview` 安装，可和既有游戏盒同时使用，收藏、缓存和游戏保存数据分别存放。
